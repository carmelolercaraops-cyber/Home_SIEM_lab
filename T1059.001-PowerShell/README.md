# T1059.001 - PowerShell

## Overview

This analysis documents a controlled laboratory exercise focused on MITRE ATT&CK technique **T1059.001 - PowerShell**.

The objective is to observe PowerShell execution through Windows endpoint telemetry, forward the generated events to Splunk, develop detection logic, validate the detection, and investigate the resulting activity from a SOC perspective.

The activity was intentionally generated using Atomic Red Team inside the Windows laboratory environment.

## Laboratory Activity

The Atomic Red Team test used for this analysis was:

- **Technique:** T1059.001 - PowerShell
- **Test:** T1059.001-17 - PowerShell Command Execution
- **Execution result:** Successful
- **Observed output:** `Hello, from PowerShell!`
- **Exit code:** `0`

The test generated PowerShell activity that was observable through multiple Windows telemetry sources.

## Telemetry

The analysis uses telemetry collected from:

- Sysmon
- PowerShell Script Block Logging
- Splunk Universal Forwarder
- Splunk Enterprise

Relevant telemetry included:

- Sysmon Event ID 1 - Process Create
- PowerShell Event ID 4104 - Script Block Logging

Sysmon provided process-level information such as the executable, command line, process ID, parent process, and hash.

PowerShell Script Block Logging provided additional visibility into the PowerShell script content.

The combination of these telemetry sources allowed the execution to be investigated with greater context than relying on a single event source.

## Detection

The detection was developed and tested in Splunk using SPL.

The detection focuses on PowerShell process creation involving encoded command execution, including:

- `powershell.exe`
- Encoded PowerShell command-line parameters such as `-e`, `-enc`, and `-EncodedCommand`
- Parent process information
- Exclusion of Splunk's own PowerShell process where necessary

The final detection logic used during the laboratory validation is stored in:

`detection.spl`

The detection criteria were derived from the characteristics observed during the investigation rather than solely from the expected Atomic Red Team test result.

## Alert Validation

A real-time Splunk alert was configured using the validated detection.

The alert workflow was tested end-to-end:

    Atomic Red Team
          ↓
    Windows / Sysmon telemetry
          ↓
    Splunk Universal Forwarder
          ↓
    Splunk Enterprise
          ↓
    SPL Detection
          ↓
    Real-Time Alert
          ↓
    Triggered Alert

The alert was successfully triggered after the laboratory activity was executed.

## Investigation Methodology

The investigation followed a structured SOC investigation workflow.

### 1. Timeline

The investigation started by establishing the time window surrounding the Atomic Red Team T1059.001-17 execution.

The relevant Sysmon and PowerShell events were then reviewed within the same activity window.

### 2. Noise Reduction

The initial telemetry contained multiple PowerShell-related events, including activity generated by the laboratory environment and Splunk itself.

The investigation therefore used process fields, command-line information, and parent process relationships to distinguish the controlled PowerShell execution from unrelated PowerShell activity.

The Splunk PowerShell process was identified as environmental activity and was excluded from the final detection where necessary.

### 3. Hypothesis

The investigation hypothesis was that the Atomic Red Team test would generate a PowerShell process executing an encoded command and that the corresponding script content would be observable through PowerShell Script Block Logging.

The investigation therefore focused on correlating:

- PowerShell process creation
- Encoded command-line parameters
- Parent process information
- PowerShell Event ID 4104

### 4. Process Investigation

The observed process chain provided additional context for the investigation.

The laboratory execution included PowerShell activity involving `cmd.exe` and an encoded PowerShell command.

Process identifiers and parent process information were reviewed to establish the relationship between the processes involved in the execution.

The encoded command was then decoded during the investigation to understand the observed execution.

### 5. Telemetry Correlation

Sysmon Event ID 1 provided process-level evidence of the PowerShell execution.

PowerShell Event ID 4104 independently provided the decoded script content:

`Write-Host 'Hello, from PowerShell!'`

The two telemetry sources were correlated to confirm that the observed process execution and script content belonged to the same controlled laboratory activity.

This provided stronger evidence than relying on the PowerShell process creation event alone.

### 6. TTP Identification

The observed PowerShell execution corresponds to **MITRE ATT&CK T1059.001 - PowerShell**.

The use of an encoded PowerShell command was treated as an investigation-relevant characteristic because encoded command-line execution can conceal the content of a PowerShell command.

The laboratory context and the correlated Event ID 4104 telemetry confirmed that the activity corresponded to the intentionally executed Atomic Red Team test.

### 7. Detection Development

After the relevant characteristics had been identified and validated, the SPL detection was developed around observable PowerShell execution and encoded command-line parameters.

The detection also includes an exclusion for the Splunk PowerShell process identified during the investigation as environmental activity.

The resulting detection logic is stored in:

`detection.spl`

Investigative pivots such as parent process relationships and decoded script content were used to understand the activity but were not automatically treated as detection criteria.

### 8. Detection Validation

The detection was tested against the generated telemetry and successfully identified the intended PowerShell activity.

The real-time Splunk alert was then validated by executing the Atomic Red Team T1059.001-17 test again.

The alert triggered successfully, confirming the complete workflow from controlled activity to telemetry, detection, and real-time alerting.
