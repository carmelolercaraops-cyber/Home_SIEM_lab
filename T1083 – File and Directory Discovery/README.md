# T1083 - File and Directory Discovery

## Objective

Detect and investigate File and Directory Discovery activity corresponding to MITRE ATT&CK technique T1083.

The detection is based on Sysmon Process Create telemetry and identifies execution of `cmd.exe` containing directory enumeration commands using `dir /s`.

---

## Atomic Red Team Test

### Technique

**MITRE ATT&CK:** T1083 - File and Directory Discovery

### Atomic Test

**Atomic Red Team:** T1083-1

The Atomic Red Team T1083-1 test was executed on the Windows lab host.

The test generated Sysmon Process Create telemetry containing directory enumeration commands executed through `cmd.exe`.

The Atomic execution subsequently timed out, but the expected Sysmon telemetry was generated and the corresponding Splunk detection was successfully validated.

---

## Telemetry

The investigation was performed using Sysmon Event ID 1 (Process Create).

Relevant fields observed during the investigation included:

- `Image`
- `CommandLine`
- `ProcessId`
- `ParentProcessId`
- `ParentImage`
- `User`
- `Hashes`

The relevant process was:

`C:\Windows\System32\cmd.exe`

The observed execution contained multiple directory enumeration commands using `dir /s` and `tree /F`.

The observed process was executed by:

`DESKTOP-PQSCESJ\Dell`

The observed parent process was:

`C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`

## Observed Command Line

The observed execution was:

`"cmd.exe" /c dir /s c:\ >> %%temp%%\T1083Test1.txt & dir /s "c:\Documents and Settings" >> %%temp%%\T1083Test1.txt & dir /s "c:\Program Files\" >> %%temp%%\T1083Test1.txt & dir "%%systemdrive%%\Users\*.*" >> %%temp%%\T1083Test1.txt & dir "%%userprofile%%\AppData\Roaming\Microsoft\Windows\Recent\*.*" >> %%temp%%\T1083Test1.txt & dir "%%userprofile%%\Desktop\*.*" >> %%temp%%\T1083Test1.txt & tree /F >> %%temp%%\T1083Test1.txt`

The command line performs recursive directory enumeration across multiple filesystem locations using `dir /s` and `tree /F`.

This behavior corresponds directly to **MITRE ATT&CK T1083 - File and Directory Discovery**.

The investigation also identified additional process activity in the surrounding time window. This activity was reviewed as contextual information but was not used as the primary T1083 detection criterion.

## Splunk Detection

The detection query used in Splunk is:

`index=siem_lab sourcetype="WinEventLog:Sysmon" EventCode=1 Image="C:\\Windows\\System32\\cmd.exe" Message="*dir /s*"`

The query was tested during the investigation and returned the relevant `cmd.exe` event associated with the observed T1083 activity.

The detection intentionally uses the combination of `cmd.exe` and `dir /s` to identify recursive directory enumeration while remaining simple to understand, reproduce, and maintain.

## Detection Flow

The detection flow is:

1. Atomic Red Team executes T1083-1.
2. `cmd.exe` is created on the Windows host.
3. The process executes recursive directory enumeration using `dir /s`.
4. Sysmon generates Event ID 1.
5. The event is forwarded to Splunk.
6. The SPL detection searches for `cmd.exe` containing `dir /s`.
7. The Splunk real-time alert triggers.
8. The event can then be investigated using the associated command line and process information.

---

## Investigation Methodology

The investigation followed a structured SOC investigation workflow.

### 1. Timeline

The investigation started by restricting the Splunk search to the time window surrounding the Atomic Red Team T1083-1 execution.

This reduced the initial event set and established the relevant period for investigation.

### 2. Noise Reduction

The initial time window contained multiple Sysmon events generated by Windows, Splunk, and the Atomic Red Team execution.

The search was refined to exclude known Splunk service activity:

`index=siem_lab NOT Splunk NOT User="NT SERVICE\\Splunkd"`

Process fields such as `Image`, `CommandLine`, `ParentImage`, and process identifiers were reviewed to distinguish relevant discovery activity from background infrastructure and precondition checks.

### 3. Hypothesis

The investigation hypothesis was that the Atomic Red Team execution would result in a Sysmon Process Create event associated with `cmd.exe` executing recursive directory enumeration commands.

The presence of `dir /s` in the process command line was therefore used as the primary investigative pivot.

### 4. Process Investigation

The investigation identified a `cmd.exe` process with the following command line:

`"cmd.exe" /c dir /s ... & tree /F ...`

The process had:

- `ProcessId`: `5376`
- `ParentProcessId`: `14032`
- `ParentImage`: `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`
- `User`: `DESKTOP-PQSCESJ\Dell`
- `SHA256`: `97AC98B1A92C286054CCE55239CFCCDFC23A5517BD07FE693072C9CA96C7DABB`

The parent-process relationship was used as an investigative pivot and was not required as a primary detection criterion.

### 5. TTP Identification

The execution of recursive `dir /s` and `tree /F` commands directly corresponds to **MITRE ATT&CK T1083 - File and Directory Discovery**.

The commands enumerate files and directories across multiple filesystem locations.

The classification was based on the observed process behavior rather than on the presence of a specific process identifier or parent-process relationship.

### 6. Detection Development

After identifying the relevant process and validating the associated telemetry, the detection was developed using the following SPL condition:

`index=siem_lab sourcetype="WinEventLog:Sysmon" EventCode=1 Image="C:\\Windows\\System32\\cmd.exe" Message="*dir /s*"`

The detection was intentionally kept simple because the execution of recursive `dir /s` commands directly represented the controlled T1083 activity observed during the investigation.

### 7. Detection Validation

The SPL detection was tested against the observed telemetry and returned the expected `cmd.exe` event containing the `dir /s` activity.

A real-time Splunk alert was then configured using the same detection logic.

The telemetry generated by the Atomic Red Team T1083-1 test successfully triggered the alert.

Although the Atomic execution itself timed out, the expected Sysmon telemetry and Splunk alert were both observed.

This validated the detection workflow from controlled activity to telemetry, detection, and real-time alerting.
