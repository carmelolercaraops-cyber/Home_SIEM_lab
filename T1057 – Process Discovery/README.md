# T1057 - Process Discovery

## Objective

Detect and investigate Process Discovery activity corresponding to MITRE ATT&CK technique T1057.

The detection is based on Sysmon Process Create telemetry and identifies execution of `tasklist.exe`.

---

## Atomic Red Team Test

### Technique

**MITRE ATT&CK:** T1057 - Process Discovery

### Atomic Test

**Atomic Red Team:** T1057-2

The Atomic Red Team test was executed successfully on the Windows lab host.

The test generated Sysmon Process Create telemetry containing the execution of `tasklist.exe`.

---

## Telemetry

The investigation was performed using Sysmon Event ID 1 (Process Create).

Relevant fields observed during the investigation included:

- `Image`
- `CommandLine`
- `ProcessId`
- `ParentProcessId`
- `ParentImage`
- `User`
- `Hashes`

The relevant process was:

`C:\Windows\System32\tasklist.exe`

The observed execution was associated with `cmd.exe` as the parent process.

---

## Observed Command Line

The observed execution was:

`"cmd.exe" /c tasklist`

The command line executes `tasklist.exe`, which lists the currently running processes.

This behavior corresponds directly to **MITRE ATT&CK T1057 - Process Discovery**.

The investigation also identified additional process activity in the surrounding time window. This activity was reviewed as contextual information but was not used as the primary T1057 detection criterion.

---

## Splunk Detection

The detection query used in Splunk is:

`index=siem_lab sourcetype="WinEventLog:Sysmon" EventCode=1 Image="C:\\Windows\\System32\\tasklist.exe"`

The query was tested during the investigation and returned the relevant `tasklist.exe` event associated with the observed T1057 activity.

The detection intentionally uses a simple process-based condition to remain easy to understand, reproduce, and maintain.

---

## Alert Configuration

A Splunk real-time alert was created using the detection query.

**Alert name:**

`T1057 - Process Discovery`

The alert was configured to monitor the detection query in real time.

The alert was subsequently validated by executing the Atomic Red Team T1057-2 test again.

The alert triggered successfully.

---

## Detection Flow

The detection flow is:

1. Atomic Red Team executes T1057-2.
2. `tasklist.exe` is created on the Windows host.
3. Sysmon generates Event ID 1.
4. The event is forwarded to Splunk.
5. The SPL detection searches for `tasklist.exe`.
6. The Splunk real-time alert triggers.
7. The event can then be investigated using the associated process and parent-process information.

---

## Investigation Methodology

The investigation followed a structured SOC investigation workflow.

### 1. Timeline

The investigation started by restricting the Splunk search to the time window surrounding the Atomic Red Team T1057-2 execution.

This reduced the initial event set and established the relevant period for investigation.

### 2. Noise Reduction

The initial time window contained multiple Sysmon events generated by both Windows and Splunk activity.

Process fields such as `Image`, `CommandLine`, `ParentImage`, `ParentCommandLine`, and process identifiers were reviewed to distinguish relevant process activity from background infrastructure and scheduled activity.

Observed process relationships were evaluated as contextual information and were not automatically treated as malicious.

### 3. Hypothesis

The investigation hypothesis was that the Atomic Red Team execution would result in a Sysmon Process Create event associated with `tasklist.exe`.

The presence of `tasklist.exe` was therefore used as the primary investigative pivot.

### 4. Process Investigation

The investigation identified `tasklist.exe` as the relevant process.

The observed process contained the following command line:

`tasklist`

The associated parent process was:

`C:\Windows\System32\cmd.exe`

with the parent command line:

`"cmd.exe" /c tasklist`

This provided additional context for the observed execution.

The parent-process relationship was used as an investigative pivot and was not required as a primary detection criterion.

### 5. TTP Identification

The execution of `tasklist.exe` directly corresponds to **MITRE ATT&CK T1057 - Process Discovery**.

`tasklist.exe` is a native Windows utility used to enumerate currently running processes.

The classification was based on the observed process behavior rather than on the presence of a specific process identifier or parent-process relationship.

### 6. Detection Development

After identifying the relevant process and validating the associated telemetry, the detection was developed using a simple process-based SPL condition:

`index=siem_lab sourcetype="WinEventLog:Sysmon" EventCode=1 Image="C:\\Windows\\System32\\tasklist.exe"`

The detection was intentionally kept simple because the execution of `tasklist.exe` directly represented the controlled T1057 activity observed during the investigation.

### 7. Detection Validation

The SPL detection was tested against the observed telemetry and returned the expected `tasklist.exe` event.

A real-time Splunk alert was then configured using the same detection logic.

The Atomic Red Team T1057-2 test was executed again and successfully triggered the alert.

This validated the complete workflow from controlled activity to telemetry, detection, and real-time alerting.
