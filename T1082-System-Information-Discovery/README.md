# T1082 - System Information Discovery

## Objective

Detect and investigate System Information Discovery activity corresponding to MITRE ATT&CK technique T1082.

The detection is based on Sysmon Process Create telemetry and identifies execution of `systeminfo.exe`.

---

## Atomic Red Team Test

### Technique

**MITRE ATT&CK:** T1082 - System Information Discovery

### Atomic Test

**Atomic Red Team:** T1082-1

The Atomic Red Team test was executed successfully on the Windows lab host.

The test generated Sysmon Process Create telemetry containing the execution of `systeminfo.exe`.

---

## Telemetry

The investigation was performed using Sysmon Event ID 1 (Process Create).

Relevant fields observed during the investigation included:

- `Image`
- `CommandLine`
- `ProcessId`
- `ParentProcessId`
- `ParentImage`
- `User`
- `Hashes`

The relevant process was:

`C:\Windows\System32\systeminfo.exe`

The observed execution was associated with `cmd.exe` as the parent process.

---

## Observed Command Line

The observed execution chain was:

`cmd.exe /c systeminfo & reg query HKLM\SYSTEM\CurrentControlSet\Services\Disk\Enum`

The command line shows two discovery-related activities:

- `systeminfo.exe` — System Information Discovery, mapped to **MITRE ATT&CK T1082**.
- `reg query HKLM\SYSTEM\CurrentControlSet\Services\Disk\Enum` — registry enumeration related to disk information.

For this investigation, the detection is focused specifically on the `systeminfo.exe` execution because it directly represents **T1082 - System Information Discovery**.

The additional registry query is documented as contextual activity observed in the same command execution and is not used as the primary T1082 detection criterion.

---

## Splunk Detection

The detection query used in Splunk is:

`index=siem_lab sourcetype="WinEventLog:Sysmon" Message="*systeminfo.exe*"`

The query was tested during the investigation and returned one relevant event for the observed T1082 activity.

The detection intentionally uses a simple process-based condition to remain easy to understand, reproduce, and maintain.

---

## Alert Configuration

A Splunk real-time alert was created using the detection query.

**Alert name:**

`T1082 - System Information Discovery`

The alert was configured to monitor the detection query in real time.

The alert was subsequently validated by executing the Atomic Red Team T1082-1 test again.

The alert triggered successfully.

---

## Detection Flow

The detection flow is:

1. Atomic Red Team executes T1082-1.
2. `systeminfo.exe` is created on the Windows host.
3. Sysmon generates Event ID 1.
4. The event is forwarded to Splunk.
5. The SPL detection searches for `systeminfo.exe`.
6. The Splunk real-time alert triggers.
7. The event can then be investigated using the associated process and parent-process information.

---

## Investigation Methodology

The investigation followed a structured SOC investigation workflow.

### 1. Timeline

The investigation started by restricting the Splunk search to the time window surrounding the Atomic Red Team T1082-1 execution.

This reduced the initial event set and established the relevant period for investigation.

### 2. Noise Reduction

The initial time window contained multiple Sysmon events generated by both Windows and Splunk activity.

Process fields such as `CurrentDirectory`, `CommandLine`, `ParentImage`, and process identifiers were reviewed to distinguish relevant process activity from background infrastructure noise.

Some observed process relationships were associated with Splunk infrastructure rather than the Atomic Red Team activity and were therefore not used as evidence for the T1082 detection.

### 3. Hypothesis

The investigation hypothesis was that the Atomic Red Team execution would result in a Sysmon Process Create event associated with `systeminfo.exe`.

The presence of `systeminfo.exe` was therefore used as the primary investigative pivot.

### 4. Process Investigation

The investigation identified `systeminfo.exe` as the relevant process.

The associated `ParentProcessId` was then used to identify the parent process.

The parent process was `cmd.exe`, and its command line provided additional context:

`cmd.exe /c systeminfo & reg query HKLM\SYSTEM\CurrentControlSet\Services\Disk\Enum`

This confirmed the relationship between the observed `systeminfo.exe` process and the surrounding command execution.

### 5. TTP Identification

The execution of `systeminfo.exe` directly corresponds to **MITRE ATT&CK T1082 - System Information Discovery**.

The additional registry query was treated as contextual activity and was not used as the primary indicator for the T1082 detection.

### 6. Detection Development

After identifying the relevant process and validating the associated telemetry, the detection was developed using a simple process-based SPL condition:

`index=siem_lab sourcetype="WinEventLog:Sysmon" Message="*systeminfo.exe*"`

The detection was intentionally kept simple because the execution of `systeminfo.exe` directly represented the controlled T1082 activity observed during the investigation.

### 7. Detection Validation

The SPL detection was tested against the observed telemetry and returned the expected `systeminfo.exe` event.

A real-time Splunk alert was then configured using the same detection logic.

The Atomic Red Team T1082-1 test was executed again and successfully triggered the alert.

This validated the complete workflow from controlled activity to telemetry, detection, and real-time alerting.
